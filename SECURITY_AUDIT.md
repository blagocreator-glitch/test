# Аудит безопасности и защиты Смета-про

Дата: 2026-05-23

## Главный вывод

Текущая версия Смета-про работает в браузере: HTML, CSS, прайс-листы и расчетная логика JS отдаются клиенту. Это значит, что полностью защитить алгоритмы от копирования на текущей архитектуре невозможно. Любой код, который должен исполнить браузер, может быть скачан и изучен.

Надежная защита логики появляется только после переноса ключевых расчетов на сервер/API: браузер отправляет параметры комнаты, а сервер возвращает готовый результат расчета.

## Что уже сделано

- Добавлен `robots.txt` с запретом индексации Смета-про, расчетных JS/JSON и служебных файлов для обычных и AI-ботов.
- Для `smeta-pro.html` добавлены meta robots: `noindex`, `nofollow`, `noarchive`, `nosnippet`, `noai`, `noimageai`.
- Добавлен `.htaccess`:
  - запрет листинга директорий;
  - закрытие `.env`, логов, backup/test/docs/scripts;
  - запрет доступа к `logs/`, `.git/`, `phpmailer/`, `scripts/`, `public_html/`;
  - security headers;
  - `X-Robots-Tag` для Смета-про и расчетных файлов;
  - кеширование статики.
- Укреплен `send-mail.php`:
  - CORS больше не отражает любой `Origin`;
  - добавлен allowlist доменов через `ALLOWED_ORIGINS`;
  - IP берется безопаснее;
  - raw JSON больше не пишется в debug-log полностью;
  - SMTP username/recipient скрыты в логах.

## Критичные остаточные риски

- Расчетная логика находится в клиентских JS-файлах (`calc-repair-quest.js`, `calc-init.js`, `calc-render.js`, `calc-pricing.js` и др.).
- Прайс-листы и каталоги доступны браузеру, если нужны для работы текущей страницы.
- `robots.txt`, `noai` и `X-Robots-Tag` помогают против добросовестных ботов, но не защищают от ручного скачивания, парсинга или недобросовестных сканеров.
- CSP пока нельзя включить строго из-за большого количества inline `onclick/onchange/oninput` и Tailwind CDN.

## Рекомендуемый следующий этап

1. Перенести расчет Смета-про на сервер:
   - `/api/calculate-room`
   - `/api/calculate-estimate`
   - `/api/panel-passport`
   - `/api/export-pdf`
2. Оставить в браузере только UI и минимальные справочники.
3. Добавить авторизацию/сессии для Смета-про или ограничение по одноразовым токенам.
4. Добавить rate limit на API и защиту от массового перебора.
5. Собрать фронтенд в production bundle с minify/obfuscation как дополнительный, но не основной барьер.
6. После удаления inline handlers включить строгий CSP.

- Не публиковать JSON-прайсы, если они больше не нужны клиенту после переноса расчетов на сервер.
- Заменить `https://cdn.tailwindcss.com` на собранный CSS-файл.
- Разделить большой `calc-repair-quest.js` на production bundle и lazy-loading модулей.
